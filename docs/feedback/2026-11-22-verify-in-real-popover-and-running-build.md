# 수정했다고 보고했는데 사용자 화면에서는 그대로였음

- 날짜: 2026-11-22
- 작업: v0.1.3 볼륨 숫자 입력란 수정

## 무엇을 지적받았나

수정과 draft 릴리스를 끝냈다고 보고한 뒤 사용자가 "아직도 그러네"라고 했다. 입력란 밖을 클릭했을 때 현재 슬라이더 값으로 반영되는지도 물었다.

## 왜 틀렸나

- 실행 중이던 VSLight는 `/Applications`의 0.1.3이 아니라 `build/Build/Products/Debug`의 0.1.2 Debug 빌드였다. 같은 번들 ID의 예전 빌드가 남아 있으면 그쪽이 실행된다. 보고에 한 줄로만 적고 넘어갔다.
- 첫 검증은 일반 창에서만 했고 `MenuBarExtra` 창에서는 하지 않았다.
- 입력란 밖 클릭으로 포커스가 풀리는지는 검사하지 않았다. AppKit은 빈 곳 클릭으로 first responder를 풀지 않는다.

## 어떻게 고치나

- UI 수정을 보고하기 전에 `build/`의 Debug 빌드를 다시 만들고 실행 중인 인스턴스를 새 빌드로 교체한다.
- "아직 안 된다"는 보고를 받으면 먼저 `ps`로 실행 중인 바이너리 경로와 빌드 시각을 확인한다.
- 포커스가 걸린 UI는 실제로 쓰이는 창 종류에서 검증하고, 포커스가 풀려야 하는 모든 경로를 검사 항목에 넣는다.

## 언제 적용하나

이 저장소에서 메뉴 막대 팝오버 UI를 고칠 때마다 적용한다.
