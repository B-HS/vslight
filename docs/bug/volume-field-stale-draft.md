# 볼륨 숫자 입력란이 슬라이더 값을 반영하지 않음

- 발견: 2026-11-22
- 수정 버전: v0.1.3
- 위치: `Sources/Features/Volume/VolumeCardView.swift`

## 증상

- 빠른 창에서 숫자를 클릭한 뒤 슬라이더를 움직이면 숫자가 클릭 시점 값에 머문다.
- 그 상태에서 입력란 포커스가 풀리면 예전 숫자가 다시 적용되어 슬라이더로 바꾼 볼륨이 되돌아간다.
- 소수점 자리가 0일 때 숫자를 클릭했다가 수정 없이 벗어나면 볼륨이 표시값으로 반올림된다. 63.7%가 64%가 된다.

## 원인

- 입력란은 `draft` 문자열을 따로 들고 있고, 포커스 중에는 `model.audio.volume` 변경을 `draft`에 반영하지 않았다.
- 슬라이더는 클릭해도 first responder를 가져가지 않아 입력란 포커스가 그대로 남았다.
- 포커스가 풀릴 때 `commit()`이 `draft`를 파싱해 현재 볼륨과 0.0005 넘게 다르면 적용했다. 사용자가 실제로 수정했는지는 확인하지 않았다.

## 해결

- 볼륨이 바뀌면 출처와 관계없이 `endEditing()`이 `draft`를 현재 볼륨으로 맞추고 포커스를 푼다. 슬라이더, 프리셋, 단축키, 시스템 볼륨 키가 모두 같은 경로다.
- `commit()`은 `draft`가 현재 볼륨의 표시 문자열과 다를 때만 값을 적용한다.

## 검증

```bash
./Scripts/verify-volume-card.sh
```

실제 `VolumeCardView.swift`를 가짜 `AppModel`과 함께 창에 띄우고 클릭, 입력, Return을 합성 이벤트로 보낸다. 수정 전 코드는 18개 검사 중 8개가 실패하고 수정 후에는 모두 통과한다.

메뉴 막대 팝오버 안에서의 동작은 자동으로 확인하지 못했다. macOS 27에서 접근성 `AXPress`로 `MenuBarExtra` 창이 열리지 않는다. 수동 확인 항목은 `docs/quality-assurance/volume-card.md`에 있다.
