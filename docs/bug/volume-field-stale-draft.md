# 볼륨 숫자 입력란이 슬라이더 값을 반영하지 않음

- 발견: 2026-11-22
- 수정 버전: v0.1.3 (볼륨 변경 시 포커스 해제), v0.1.5 (입력란 밖 클릭 시 편집 종료, Return으로만 적용)
- 위치: `Sources/Features/Volume/VolumeCardView.swift`

## 증상

- 빠른 창에서 숫자를 클릭한 뒤 슬라이더를 움직이면 숫자가 클릭 시점 값에 머문다.
- 그 상태에서 입력란 포커스가 풀리면 예전 숫자가 다시 적용되어 슬라이더로 바꾼 볼륨이 되돌아간다.
- 소수점 자리가 0일 때 숫자를 클릭했다가 수정 없이 벗어나면 볼륨이 표시값으로 반올림된다. 63.7%가 64%가 된다.
- 입력란 밖의 빈 곳이나 다른 버튼을 클릭해도 입력란 포커스가 풀리지 않는다.

## 원인

- 입력란은 `draft` 문자열을 따로 들고 있고, 포커스 중에는 `model.audio.volume` 변경을 `draft`에 반영하지 않았다.
- 슬라이더는 클릭해도 first responder를 가져가지 않아 입력란 포커스가 그대로 남았다.
- 포커스가 풀릴 때 `commit()`이 `draft`를 파싱해 현재 볼륨과 0.0005 넘게 다르면 적용했다. 사용자가 실제로 수정했는지는 확인하지 않았다.
- AppKit은 창의 빈 곳을 클릭해도 텍스트 필드의 first responder를 풀지 않는다.

## 해결

- 볼륨이 바뀌면 출처와 관계없이 `endEditing()`이 `draft`를 현재 볼륨으로 맞추고 포커스를 푼다. 슬라이더, 프리셋, 단축키, 시스템 볼륨 키가 모두 같은 경로다.
- 편집을 시작하면 마우스 다운 로컬 모니터를 걸고, 입력란 밖을 클릭하면 `endEditing()`을 호출한다. 편집이 끝나면 모니터를 제거한다.
- 입력한 값은 Return으로만 적용한다. Return 없이 포커스를 잃으면 입력을 버리고 현재 볼륨을 표시한다.
- `commit()`은 `draft`가 현재 볼륨의 표시 문자열과 다를 때만 값을 적용한다.

"Return으로만 적용"은 "밖을 클릭하면 현재 슬라이더 값으로 반영"이라는 요청을 해석한 결과다. 밖을 클릭했을 때 입력값을 적용하는 쪽으로 바꾸려면 `VolumeCardView`의 `onChange(of: isEditing)`과 모니터 핸들러에서 `endEditing()` 대신 `commit()`을 호출한다.

## 검증

```bash
./Scripts/verify-volume-card.sh
```

실제 `VolumeCardView.swift`를 가짜 `AppModel`과 함께 `MenuBarExtra` 창에 띄우고 클릭, 입력, Return을 합성 이벤트로 보낸다. v0.1.2 코드는 일반 창에서 돌린 첫 18개 검사 중 8개가 실패했다. 지금의 24개 검사 기준으로 밖 클릭 처리 전 코드는 4개가 실패하고 현재 코드는 모두 통과한다.

스크립트는 팝오버를 열기 위해 실제 클릭을 한 번 보내고 커서를 원래 위치로 되돌린다. macOS 27에서 접근성 `AXPress`, `performClick`, 합성 `NSEvent`로는 `MenuBarExtra` 창이 열리지 않는다. 터미널에 손쉬운 사용 권한이 필요하다.
